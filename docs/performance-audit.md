## Required gates

- Property tests and deterministic work, capacity and retention bounds.
- Real bundled-engine cache, cancellation and malformed-input fixtures.
- Fixed-DPI page pixels and extracted text against pinned upstream pdfTeX.
- Release-mode paired timing on free GitHub Intel and ARM runners.

The timing gate still requires 128 pairs and 32 balanced crossover units per
case. Its practical regression boundary is 10%, relative median absolute
deviation limit is 10%, and order-bias limit is 5%. Exit code 2 is blocking.
Diagnostic profiles and same-binary controls cannot replace a primary result.
The final comparison must use the actual `main` commit as baseline.

## Release blockers

The reproduced failures now have implementations and local regression tests.
Full remote verification of these changes is pending. Every fixture is a
required assertion, with no known-failure exemption.

| Failure | Change |
| --- | --- |
| Input changes during a build become a fresh cache entry | Capture a generation before compilation and validate it before publishing cache state. |
| New higher-priority inputs do not invalidate a cache hit | Retain bounded lookup-directory and alias identities as dependencies. Unchanged warm checks inspect metadata only. Changed directories use direct membership hashes without recursive enumeration. |
| Textual end markers hide active bytes | Hash complete source bytes rather than guessing execution from textual markers. |
| Replaced compressed formats reuse stale raw companions | Materialize into a private content-addressed cache, retain source dependencies and recover corrupt cache entries. Never write adjacent installation companions. |
| Parent cancellation leaves child processes running | Own subprocess groups, forward CLI cancellation, escalate stubborn groups and reap direct children. |

Auxiliary commands share an eight-child ceiling. Its CI fixture checks completed
outputs and maximum overlap, rather than treating completion as a scaling claim.
SIGKILL cannot execute parent cleanup. Library callers retain their signal policy
and must not independently reap children owned by the build scheduler.

Output ownership covers equal and parent/child build folders. Sorted,
deduplicated descriptor locks prevent lock-order deadlocks. Cleanup holds an
exclusive lease while builds share it. Persistent lock retention is bounded by
769 files. Hash collisions can serialize unrelated folders, and continuous
builds can postpone cleanup. These guarantees require cooperating upgraded
processes. Custom caches placed inside another build's output folder still need
separate placement constraints.

Global bibliography restoration validates the dependencies selected by the
current invocation before copying cached output. Publication is serialized.
Auxiliary source aliases remain dependencies, and malformed owned cache metadata
causes a rebuild. State replacement is atomic, without a power-loss durability
guarantee.

Implicit project lookup does not enumerate historical files in owned output
trees. Files opened for output, or explicitly opened for input there, become
available through a separate current-pass ledger capped at 4 MiB. Eviction and
oversized-index fallback preserve those observations. Arbitrary files created
and consumed during compilation decline build-cache publication until the
engine can prove which generated bytes it consumed. Every draft and final pass
records dependencies. A separate bounded whole-build ledger retains output
observations before the next pass replaces its recorder.

## Rust migration

Local macOS workspace checks pass with C and C++ compilers disabled. CI now
enforces this for candidate builds. BibTeX uses a Rust-only bridge, and
compression uses Rust backends. Tekai's release support remains macOS.
The engine stays a Rust library. Release builds retain fat LTO.

Rust now owns engine allocations, decimal/integer formatting and engine streams.
Streams own files, console access, pipes and gzip codecs. Read and write buffers
have explicit bounds. EOF, write failures and retries cannot replay old input or
grow retained output without limit. Compatibility properties use native
formatting and stream implementations as test-only oracles.

Integer prefix conversion also uses Rust byte slices, with constant storage,
linear digit work, explicit overflow and consumed offsets. The replaced native
integer functions remain test-only oracles. Actual CLI cases cover SyncTeX base selection and
epoch success and failure paths.

TrueType glyph selection and composite references check their array domains.
Reserved glyphs own their output slots once. Unsigned optional indices replace
the signed sentinel. An owned four-glyph font fixture verifies actual embedded
outlines, metrics and every byte-code mapping. This is not a complete hostile
font parser. The post table now has a checked Rust parser and stack-owned indexed
names. One pass reads the referenced string prefix, and glyph lookups do not
repeat string walks. Output indices preserve the full unsigned range. An owned
304-glyph font verifies all 302 custom names across the old 256-name wrap, and
malformed records fail through ordinary diagnostics. Legacy non-NUL name bytes
through 255 bytes remain accepted. Other name-table records and font-table
readers still need checked ownership and bounds.

Initialization now uses ordinary Rust calls. The core modules share one type
family and checked state imports instead of duplicated external declarations.
Layout tests pin field offsets and union-byte views to preserve existing format
files. Rounding and termination also use checked Rust calls. Backend ABI
connections and global ownership remain unfinished.

The combined local checkpoint through `3dc1ef2` passed 709 workspace unit tests,
including 233 engine tests, with 512 property cases. It also passed 14 no-system-TeX lookup
tests, 11 compiler cache tests, 17 self-contained CLI tests, two SyncTeX/epoch
tests, 364 Python policy tests and all required
runtime regression probes. Fresh format generation and loading passed. All 99
pages matched pinned reference pixels and extracted text. Strict Clippy,
Rust 1.89 checks and the standalone engine build passed with C and C++ compilers
disabled. The final candidate must repeat the required gates in CI.

The exact engine still contains substantial pdfTeX-derived algorithms,
raw-pointer callers, internal ABI connections and mutable global state. Native
formatted scanning, string utilities, option parsing and regex remain to be
replaced.
The Rust regex prototype is not production-ready. The remaining backend families
need shared types and invocation-owned state. Necessary OS interfaces remain.
Repeated in-process execution and leak freedom are not established. Remote
timing for the new implementation is pending.

Checked Rust backend cursors now validate SFD fields, inclusive ranges and
destination capacity. Map-name assembly reserves its suffix and terminator
before copies. Type1 copies validate both complete intervals. Overlength
ToUnicode normalization returns a warning without changing the prior mapping.
The owned CLI fixtures exercise valid boundary values and each rejection path.

The Rust entry owns its argument bytes and claims permanent single entry before
reset or initialization. Normal completion returns a typed result after flushing
streams. One argument set stays alive for globals that borrow it. This prevents
the entry from replacing borrowed backing or reinitializing global workspace
pointers. Full invocation-owned engine state is still unfinished. Fatal exits
bypass Rust drops, and several destructors leave stale global roots. Catching a
panic across existing non-unwinding internal calls is not a safe replacement for
process termination.

Cache generation checks use filesystem metadata, including change times, to
detect concurrent edits. They are not a snapshot filesystem. Cold dependency
inventory can still revisit a directory already traversed by engine lookup.
Unchanged warm checks do not recursively enumerate directories.

## Remaining performance work

Completion checks do not establish good asymptotic behavior. These costs remain
open unless a dedicated operation-count test proves otherwise.

- Repeated prefix scans and string edits in large formatting requests.
- Repeated column and escape scans in long lint inputs.
- Loading unrelated sidecars from settled auxiliary caches.
- Cloning shared PDF resources per page.
- Cloning expansion state for mutable local groups.
- Re-reading the same recorder during auxiliary phases. Streaming removes full
  file copies and duplicate retained paths, but the longest row and unique
  dependency sets remain uncapped.

Full-byte hashing now uses 64 KiB of scratch per active call. An output snapshot
has at most eight hash workers, so its hash scratch is at most 512 KiB. This
does not bound total process memory or concurrent independent builds.

The warm-cache benchmark searches project inputs without redundantly making
generated output a recursive source tree. Such explicit output searches
intentionally decline cache publication. The corrected workload still verifies
all 1024 genuine inputs, a real cache hit and unchanged state identity. Post-exit
oracle failures retain bounded command IDs, arguments and captured output.

The active experimental renderer remains research code. Its general page parity
is not established. Retired proposal-only modules and the redundant manual
attribution route are recoverable from Git history.
